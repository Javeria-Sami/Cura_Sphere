Software Requirements Specification (SRS)
CuraSphere - Hospital Management System
Section 6 - Non-Functional Requirements (NFR)

6.1 Introduction
The Non-Functional Requirements (NFR) define the quality attributes, operational characteristics, constraints, and standards that govern the CuraSphere Hospital Management System.
Unlike functional requirements, which describe what the system does, non-functional requirements describe how well the system performs.
These requirements ensure that CuraSphere is:
Secure
Reliable
Available
Scalable
Maintainable
High Performing
Easy to Use
Easy to Deploy
Easy to Monitor
Easy to Upgrade
Enterprise Ready
The NFRs apply across every module of CuraSphere including Patient Management, Billing, Pharmacy, Laboratory, HR, Inventory, Security, Reporting, and Integrations.

6.2 Purpose
The purpose of this section is to define the minimum quality standards that every component of CuraSphere shall satisfy during development, deployment, operation, and maintenance.
These requirements ensure that the system delivers consistent performance while supporting hospital operations 24 hours a day.

6.3 Objectives
The Non-Functional Requirements shall:
Ensure high system performance.
Maintain continuous availability.
Protect sensitive healthcare information.
Support future scalability.
Improve maintainability.
Simplify deployment.
Support disaster recovery.
Ensure interoperability.
Improve usability.
Ensure regulatory compliance.
Support DevOps practices.
Enable cloud deployment.
Improve monitoring capabilities.
Reduce operational risks.
Support long-term software evolution.
